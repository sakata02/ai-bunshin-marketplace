# 依頼の受け付け

本人は「これやっといて」「○○と○○は守って」程度に雑に振ってよい。**要件は AI が案を作り、本人は確認するだけ**にする。

## 00. 本人の仕事か、AI への依頼か

tasks.json に登録する前に、先に `.claude/ai-bunshin-details/tasks-json.md` を読む（一度読んだら、この会話では読み直さない）。

- 「タスク追加：…」「自分のタスクに入れて」「やること：…」のように、**本人が自分でやる仕事** を言われたら、AI への依頼ではなく **本人の仕事** として登録する：`assignee`＝本人の名前（config の owner）、`kind: 自分`、`type: 本人の仕事`。期日は言われたときだけ入れる（聞き返さない）。手順・理由は不要
- **まとめて登録**：1行に「、」区切り、箇条書き、貼り付けたメモや Excel の表のどれでもよい。1件ずつタスクにし、「（〆11/5）」「11/5まで」「明日」「来週月曜」などは期日に直す（今日の日付から計算。曖昧なら期日なしにして note に原文を残す）。部署は分かれば入れる
- 登録したら、一覧で返す（ID・仕事・期日）。続けて **AI が引き受けられる部分** を一言：「T0XX（資料の下書き）と T0YY（データの集計）は AI が引き受けられます。引き受けますか？」
  - OK なら、その部分を AI のタスクとして新しく登録し（振り分けの表で作る人・確かめる人を決める）、本人の仕事の `note` に「AI に渡した：T0ZZ」、AI のタスクの `related` に本人の仕事の ID を入れる
  - 本人の仕事は残す（最後の判断・提出・出席などは本人）
- 明らかに繰り返しの仕事・手作業の多い仕事（毎週の集計、転記、同じ連絡）なら、「これはシステム化の候補です（金曜の改善の提案で詳しく出します）」と一言添える
- AI が見て判断し、人が確かめるところだけ人に残せる仕事（例：届いた書類を見て確認・下書きする）なら、「寄り添い型の候補です」とも添える
- 終わったと言われたら完了（`done_date`）。本人の仕事はポイントに数えない

## 0. 急ぎかどうか（3段階）

| 本人の言い方 | 動き | 記録 |
|---|---|---|
| 「今すぐ」 | **その場で対応する**（会話の中で /ai-bunshin:sprint の手順。部下も使う） | タスクとして登録し、終わったら完了にする。今日の daily_sprints の `added` に入れ、振り返りでは「割り込み」として扱う |
| 「今日中」「急ぎ」 | 登録して **今日の計画に割り込ませる**。代わりに外すタスクを一言伝える。**実行は会話の中で /ai-bunshin:sprint の手順で行う**（朝の自動実行がもう終わっていても進められるように） | 今日の daily_sprints の `added` に入れる（`committed` は変えない）。外したタスクは `carried_over` に入れる |
| 何も言わない／「◯日まで」 | **登録だけ**。翌営業日9時の計画に入る | 完了予定日はスクリプトが計算する（今日の計画の後に登録したものは翌営業日から） |

- 何も言われなければ急ぎではないものとして扱い、「優先度◯位、◯/◯(曜)完了予定です。急ぎなら言ってください」と1行で返す
- 今日の計画がまだないとき（9時前）の「今日中」は、優先度1位にして9時の計画に入れる

## 1. 依頼を整理する（指揮官が分析する）

tasks.json に登録する前に、先に `.claude/ai-bunshin-details/tasks-json.md` を読む（一度読んだら、この会話では読み直さない）。

依頼から次を読み取る。読み取れない項目は推測で埋め、推測したことを回答で伝える。

| 項目 | 内容 |
|---|---|
| 部署 | 本人設定の「担当部署」のどれか / 共通 |
| 種類・作る人・確かめる人 | 指揮官ルールの「振り分け」の表で決める（`type`：資料／調査・分析・設計／開発／分析／研修／本人、`assignee`・`reviewer`）。本人設定の `team.off` の部下には振らない。当てはまる部下がいない仕事は「役を渡して頼む」（`note` に「役：◯◯」）。種類が混ざる依頼はタスクを分ける。回答に「T0XX は◯◯なので部下◯（確認は部下◯）」と1行 |
| デザイン（`design`） | 指揮官ルールの「デザイン（部下E）が入るか」で判断して `true`／付けない。本人設定に入れない仕事の決まりがあれば従う。入れるなら回答に「デザインは部下E」と添える |
| 開発の場合 | `/ai-bunshin:dev` の 0 で、案件（`dev_project`）・モード・どこまでやるか（`dev_scope`）を決めて回答に1行（「◯◯（git）で、設計までにします」） |
| ゴール | 何ができたら完了か（1文） |
| 成果物 | Excel / PowerPoint / 文書 / 分析結果 など |
| 受け入れ条件 | チェックできる形で 2〜5 個 |
| 元データ | `03_インプット/<部署>/` にあるか |
| 納期 | 本人が言った場合だけ |
| ポイント | 指揮官ルールの「ポイントの基準」（`.claude/ai-bunshin-details/tasks-json.md`。基準のタスクとの比較。1/2/3/5、8 は分割）。迷うときは空欄にして、9時のプランニングで見積もる（空欄のタスクは完了予定日が出ず「見積もり待ち」と表示される。回答では下の「見積もり待ちの場合」の言い方で伝える） |

## 2. 聞き返しは最小限（要件は計画のときに詰める）

- **中身が分からないとまったく始められない点だけ** を、**1回でまとめて** 質問する
- **納期は聞き返さない**
- 推測で進められるなら質問しない。要件（ゴール・読み手・受け入れ条件）の案は、前日17時の振り返りか9時の計画で作り、本人に「この理解で進めます」と確認を出す
- **件数や残すものが揺れやすい依頼**（例：配信リストの件数、研修資料で元の文章を残すか）は、最初に「この条件で進めます」と案を添えて確認する
- **依頼したその場で一緒に詰めるもの（例外）**：社外に出すもの、会社としての判断、お金・人事、5pt 以上の大きい依頼、初めての種類の仕事、「誰に・何のために」が推測できないもの。この場合は、要件の案を出して、その場で本人に確かめる

## 2.5 要件が変わったとき

本人が「やっぱり○○も」「範囲を変えて」と言ったとき：
| タスクの状態 | すること |
|---|---|
| まだ始めていない（Backlog・ToDo） | 要件を直し、`"reestimate": true` を付ける（次の計画で見積もり直す） |
| 始めている（作業中・レビュー） | **ポイントは変えない**。増えた分を差分タスク（「T0XX の追加分：…」）として新しく登録し、見積もる |

## 3. 優先順位を決める

`04_ナレッジ/判断基準.md` の優先順位ルールに従う。ルールが未設定の間は次の順で判断する。

1. 本人が「急ぎ」と言ったもの
2. 納期が近いもの
3. 他のタスクの前提になるもの（依存関係）
4. 部署・業務の重要度（判断基準.md）
5. 小さくすぐ終わるもの

新しいタスクを tasks.json に追加し、**全タスクの `priority` を 1 から振り直す**（重複させない）。

## 4. 完了予定日を計算して回答する

tasks.json を更新すると hook が完了予定日を計算して返す（または `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/update_dashboard.py"` を実行する）。その結果を使って回答する。

**納期の指定がない場合：**

> 承知しました。「◯◯」を登録しました（T0XX）。
> 優先度 **3位** で、**11月5日(木)** に完了予定です。もっと早く必要なら言ってください。

**見積もりが空で「見積もり待ち」の場合（完了予定日は出ない。日付を作って答えない）：**

> 承知しました。「◯◯」を登録しました（T0XX）。見積もりがまだ無いので、明日 9 時の計画で見積もってから、完了予定日をお伝えします。

**納期の指定がある場合：**

- 間に合う → 「◯月◯日の納期に対し、◯月◯日に完了予定です（余裕◯日）」
- 間に合わない → 調整案を出す。例：「T004 を後ろに回せば間に合います。どうしますか？」
  - 本人が決めるまで、他のタスクの順位は勝手に下げない

推測した項目があれば最後に一言添える（例：「研修向けの資料と想定しています」）。

## 5. 本人の作業が含まれる場合

申請・判断・送付・確認など、本人にしかできない部分は、指揮官ルールの「本人へのお願い」に従って担当が本人（config の owner）のタスクとして別に登録する。**期日は AIが決めて必ず付ける**（後続の納期から逆算）。回答の最後に「📌 <呼び方>へのお願い（新規 N件）」として、期日付きで示す。

## 6. すぐ着手する場合

優先度1位で、ほかに作業中のタスクがなく、**本人が「今すぐ」「今日中・急ぎ」と言ったときだけ**、そのまま `/ai-bunshin:sprint` の手順で着手してよい。何も言われなければ登録だけして翌営業日の計画へ（上の「0. 急ぎかどうか」）。
