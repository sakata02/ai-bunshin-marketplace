## 振り返りと Try（毎日の改善）

- セッション開始時に hook が出す「実施中の Try」は、その日の作業で必ず守る。部下への指示書の「守ること」にも入れる
- Try の出口は、エージェントのプロンプト（rules・skills・agents）の変更案にする。その場の作業の直しだけで終わらせず、仕組みに残す
- 「直近の振り返り」が出ていたら、最初に一言伝える（明日の Try と、承認待ちのルール変更があればそれも）
- **ルールやプロンプトの変更は本人の承認制**。振り返りで定着と判定した Try は「ルール変更の承認」のお願いとして、**行き先（本人／共通）と理由** を付けて出し、承認されてから書き込む（手順は `/ai-bunshin:daily-review` の「承認されたとき」）
  - 本人 → 本人設定（CLAUDE.md）の「育ったルール」の表
  - 共通 → **メンテする人（config の `maintainer: true`）だけ** が、プラグインの元（マーケットプレイスのフォルダ）を直し、バージョンを上げ、CHANGELOG.md に「何を・なぜ・どの Try から」を書く。**メンテする人でなければ書き換えない**：本人の分は「育ったルール」に入れて先に使い、共通に入れてほしい提案の下書き（何を・なぜ・試した結果）を `02_成果物/共通/` に作って、配布元へ送るお願いにする（送るのは本人）
  - Claude Code が読み込んでいるプラグインのコピー（`~/.claude/plugins/` の下）は、誰の環境でも書き換えない（更新で消えるうえ、元とずれる。NG の見張りでも止める）
  - NG の見張りは Edit・Write と Bash の書き込み（`>`・cp・mv・tee・sed -i・python の書き込みなど）を止める。本人の許可する例外（`ng_allow`）でも、この保護は外れない。見張りは文字の並びで判断するので、すり抜ける書き方があってもやらない
  - 書き込む前に元のファイルを `04_ナレッジ/ルール履歴/` に保存する。「戻して」と言われたらそこから戻す
- 自動実行の止め方：本人に `! launchctl unload ~/Library/LaunchAgents/com.ai-bunshin.daily-{plan,review}.plist` を案内する
- **Try は、良くするものの3つの見出しで分ける**（議事録の表では「良くするもの」の列に書く）。人間側の Try も、`/ai-bunshin:daily-review` の「確かめ方必須」は守る（書けない Try は採用しない）：
  - **プラグインの品質**：共通の不具合・使いにくさ。出口はプラグインの元の直し（メンテする人）
  - **チームの品質**：個人＝部下の定義・相互作用・プロセス・ツール・完成の定義・要件定義。出口はプロンプト・定義・手順の変更案
  - **人間側のやり方**：AI に頼めるのに本人が手作業でやっていること。出口は業務改善の提案（提案の一覧の「候補」）。確かめ方の例：「翌日の振り返りまでに、提案の一覧の「候補」に1行足されているか（提案にするかは金曜に決める）」
