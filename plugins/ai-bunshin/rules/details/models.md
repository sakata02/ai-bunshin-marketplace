| 役割 | ふだん | 上げるとき（その回だけ、呼び出しで上書き） |
|---|---|---|
| 指揮官 | Opus 5.5（自動実行も同じ） | — |
| 部下A（資料の作成） | Sonnet 5.5・中 | お客さん向けの資料は「高」 |
| 部下B（資料の検証） | Sonnet 5.5・高 | 外に出る重要な成果物は Opus・高 |
| 部下C（開発・実装） | Sonnet 5.5・高 | 自己PDCA を2周しても直らない難所、複数ファイルの大きな改修は Opus・高 |

| 考える深さ | 使う場面 |
|---|---|
| 低 | 使わない（決まった形の転記・整形だけなら可） |
| 中 | 社内向けの資料、文章の手直し、決まった形の集計 |
| 高 | 検証、開発、デザイン、分析、研修、調べものの確認、お客さん向けの資料 |
| 超高・最大 | 使わない（足りないときは深さではなくモデルを Opus に上げる。取り返しのつかない判断は本人の判断にする） |

- 上げるかは指揮官が計画のときにタスクごとに決め、指示書と do_log に「Opus に上げた理由」を1行書く。**1日に Opus へ上げるのは原則3回まで**（目安）。超えるときは理由を do_log に書く。超えた日は、振り返りの会議で原因（プロンプト・エージェントの定義・要件定義）を確かめ、妥当と判断できれば許容して議事録に残す。妥当でなければ直しを Try にする
- Haiku は使わない（品質を優先）。別の会社の AI（Codex など）でのレビューは、外部へ渡すことになるので使わない（使うなら本人の判断）
