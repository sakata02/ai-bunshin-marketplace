## 控え（本人のフォルダのローカル Git）

- **何のためか**：本人のフォルダをローカルの Git で記録し、直しすぎたときに1ファイルだけ昨日の状態へ戻せるようにする。外には何も送らない。開発の案件（`05_開発/` やリポジトリ）の Git とは別の仕組み
- **始め方**：`/ai-bunshin:setup` が、Git があるときに `git init` と `.gitignore`（雛形 `templates/gitignore.txt`）を置く。Git が無い人は、控え無しでも動く（変更前のコピーは `04_ナレッジ/ルール履歴/` に残る）
- **使えるか確かめる**：会話の中でコミットする前に、`git rev-parse --show-toplevel` を実行する。出力が本人のフォルダと一致するときだけ、控えとして使う。一致しないとき（親のフォルダのリポジトリなど）・Git が無いとき・リポジトリでないときは、控えとして扱わず、何もしない（本人に聞かない）
- **いつコミットするか**
  1. 夕方の振り返りの最後に、1日1回。メッセージは「YYYY-MM-DD 振り返り」。会話の中で振り返りを動かしたときは `/ai-bunshin:daily-review` の最後の手順で行い、自動実行では `scripts/auto/daily_cycle.sh` が行う（AI の中ではしない）
  2. 会話の中で区切りがついたとき（作業がひと区切りついた、本人が「いったん終わり」と言った、など）。メッセージは「YYYY-MM-DD <何をしたか>」
- **コミットのしかた**：`git add -A && git commit -m "YYYY-MM-DD <メッセージ>"` まで。「コミットするものが無い」という失敗は、すでに記録されているので成功として扱う。それ以外の失敗は、理由を本人に1行伝えて先へ進む（作業は止めない）。会話の中でだけ git の add・commit を使ってよい（自動実行の AI の中では使わない）
- **入れないもの**：`.gitignore` が決める（`03_インプット/`・xlsx・予定のキャッシュ・ログ・共通ルールの自動コピー・作業のたびに変わる一時ファイルなど）
  - 控えに入れないもの（秘密・大きいファイル）は `.gitignore` で外す。秘密の情報（パスワード・鍵・トークン）は本人のフォルダに置かない（`git add -A` で控えの履歴に入ると、あとから消せない）
- **戻すとき**（本人が「戻して」「昨日の状態に」と言ったとき）
  1. 戻すファイルを確かめる（本人のフォルダの中の1ファイル。複数なら1つずつ）
  2. 戻す先のコミットを探す：`git log --oneline -- <ファイル>` を実行し、候補（日付・メッセージ）を本人に見せて選んでもらう
  3. `git checkout <コミット> -- <ファイル>` でそのファイルだけ戻す。**`<コミット>` を必ず付ける**（付けずに `git checkout -- <ファイル>` と書くと、まだコミットしていない変更が消える）
  4. 戻したことと、戻した先のコミットを本人に1行で伝える。次の区切りのコミットに入る
  - `reset --hard` は使わない（フォルダ全体が戻って、ほかの作業を失う）
- **push**：本人が行う（外へ送るので NG）。本人が `ng_allow` に例外を入れたときだけ、本人設定の「許可する例外」に従う。控えの送り先を作るかは本人の判断で、AI は作らない・送らない
