# T066 自動実行の上限 — 設計（v2）

作成：指揮官／確かめ：部下D／実装：部下C

v1 の C（自動実行の Python）は、部下D の確認（Opus）で不合格になった。文字で止める方式は守りにならず、ふつうの分析も誤って止まる。方式の判断は坂田さん（T120）に回し、実装は T119 に分けた。**このタスクでは Python の許可に触らない。**

## ゴール（なぜ）
自動実行が手戻りを重ねて使用量を使い切らないようにする。今は周回の上限が段ごとにしかなく（各3周）、重ねると最大27周になる。`claude -p` に手数の上限も無い。

## 確かめた事実（部下D の実験）
- `claude -p --max-turns N` は `--help` に載っていないが動く。テキスト形式で超えると、標準出力の最後の行が `Error: Reached max turns (N)`、終了コード 1、標準エラーは空
- 部下の手数は親に数えられない（1回の確認）。**`--max-turns` で止まるのは指揮官の手数だけ**。部下の中は時間の上限と、B の呼び出しの上限で抑える

## A. 手数の上限（daily_cycle.sh）
- `claude -p` に `--max-turns` を付ける。既定：計画 100／実行 300／振り返り 100。config の `auto.max_turns` で段階ごとに変えられる
- 値は1以上の整数だけ通す。`abc`・`0`・負の数・`1.5`・`true`・辞書や配列・読めない config のときは、**その段階の既定**に戻す（今の時間の上限のように、どの段階でも同じ値に戻さない）
- 見分け方：終了コード 1 かつ、出力の最後の行が `^Error: Reached max turns \(\d+\)$`。文面が変わったらふつうの失敗として扱う（安全な側）
- 超えたら、時間の上限のときと同じく作業中のタスクと `daily_sprints` はそのまま残す。ログと通知は「手数の上限（N回）で〜を止めました。続きは会話で」
- 印：`last_timeout.txt` に4列目の種類（`minutes`／`turns`）を足す。4列目が無ければ `minutes` と読む（古い記録も読める）。文面に「300分」と出さない。直す先：`watch_check.py` の印の書き読み、`daily-plan`・`daily-review`・`daily-do` のその説明
- 時間の上限（計画 60・実行 180・振り返り 60 分）は変えない

## B. 周回の上限（skills）
- `daily-do`・`sprint`・`dev` に足す：**1タスクで部下を呼ぶのは、その日の合計8回まで**
  - 数える：作る・確かめる・デザインの呼び出しと、SendMessage での続き。数えない：Check 会議、「今どこ？」の確認
  - 範囲はその日だけ。持ち越したタスクは翌朝0から数える
  - 数え方：do_log の開始の行。デザインと続きも開始の行を書く
- 今の「最大3周」「同じ失敗が2回続いたら3周目に入らない」は残す。**どれかに先に届いたら止める**
- 自動実行：届いたら止めて `blockers` に「手戻りの上限」と書き、次のタスクへ
- 会話の中：止めずに、指揮官が内容を見て続けるかを決め、本人に1行伝える。上限は天井で、確かめの回数の目標ではない（坂田さん「確認の回数は内容で決める」）
- `sprint` の「部下を出したら」9 の「差し戻しの往復の上限は、ここでは決めない（S10）」を、この決まりへの参照に直す
